# Launchpad v1

Build a local, keyboard-first macOS launcher with Stacks models, stx, ts-css and Craft. Command + Space brings a compact search palette to the front from another app. Data stays in the app's Application Support directory. No account or remote service is required.

## Scope

| Capability | v1 delivery | Qualification |
| --- | --- | --- |
| Application launcher | Search, fuzzy ranking, Return to open | Real native window and cross-app hotkey test |
| Calculator | Bounded arithmetic, powers, percentages, copy result | Parser tests plus native copy |
| Quicklinks | Named URLs and encoded search arguments | Persistence, scheme validation and actual browser opening |
| Snippets | Named reusable text, aliases, copy | Model validation and native clipboard |
| Favorites and recents | Per-item favorites, usage ranking | Survive an application restart |
| Clipboard History | Opt-in automatic text capture, preview, retention, pause and clear | Native capture, protected types, local persistence |
| Appearance | System, Light and Dark | Real native screenshots in both modes |
| GitHub | Repository, issue, pull request and personal work views | Public API search, Keychain token, safe external URLs |
| Local activity | UUID events, sessions, categories, timestamps and timezone offsets | Idempotent local API, pause/delete, aggregation tests |
| Pantry | Full catalog, original logos, installed results in All, authenticated CLI jobs | Real CLI, font and app installation, restart recovery |
| App Store delivery | Sandboxed signed package, accurate metadata and screenshots | Signed launch, upload processing, review approval |

Year-review image export, arbitrary extensions, global text expansion and window control are separate issues. They must have verified privacy and platform support before inclusion. A local feature build is not proof of sandbox compatibility or App Store approval.

## Data flow and architecture

The Craft host launches stx's compiled backend and owns its lifetime. stx creates an ephemeral loopback session with a one-time token, HttpOnly cookie, same-origin and Host checks. The page uses same-origin fetch. The backend opens SQLite through `@stacksjs/orm/native`, with an explicit registry of the app's Command, LaunchRecord, ClipboardEntry, AppPreference, LauncherActivity and CatalogPackage models. Their `useApi` traits declare CRUD; writes use native model validation and fillable fields. Destructive schema upgrades fail before commit.

Application search reads the standard application directories. Launching uses Craft's NSWorkspace-backed shell interface. Systemwide shortcuts use Craft's Carbon registration, and must be proven by actual key presses while another application has focus. A registration conflict is reported in the UI.

The native model adapter is a reusable framework addition. Launchpad links the built core package during development and must pin a published version containing it before reproducible release qualification. Pantry owns immutable runtime provisioning, signing, notarization, packaging and delivery. Application code must not duplicate those processes.

## Verification matrix

| Scenario | Required result |
| --- | --- |
| Cold start without installed Bun | App and bundled backend become ready |
| Press Command + Space in another app | Existing palette appears and focuses search |
| Conflicting shortcut | Explicit error, no false registration success |
| Search, arrows, Return, Escape | Selected item launches; palette dismisses and reopens |
| Command + Delete | Clear the search without deleting a saved item |
| Click another application | Dismiss through native focus loss |
| Pantry view | Browse every catalog entry, filter kinds, preserve upstream logos |
| Pantry installation | Exact catalog targets, visible status and bounded output |
| Restart during installation | Restore client-owned job status; no duplicate install |
| Invalid command fields | 422, no invalid database row |
| Create snippet and restart | Snippet survives and copies accurately |
| Favorite and relaunch | Favorite remains and ranks first |
| Unauthorized loopback request | 403 before data access |
| New additive model column | Existing rows survive |
| Destructive model diff | Refused atomically |
| Sandboxed signed launch | Same behavior inside the actual app container |
| Store package upload | Apple reports accepted upload and processed build |

## Release sequence

1. Complete and qualify the core native model adapter; publish Stacks patch.
2. Install that version in Launchpad; remove the development link and repeat verification.
3. Commit as Chris and fast-forward origin/main. Configure the Pantry reusable workflow.
4. Run `bun run release:patch` for the installable qualification build.
5. Complete remaining v1 acceptance criteria and signed sandbox qualification.
6. Cut marketing version 1.0.0 with an immutable numeric build number. Use `buddy desktop:apple:publish --build-number N` for shared qualification, upload, processing and listing preparation.
7. Complete truthful privacy, age, export and pricing declarations. Use `buddy desktop:apple:submit --build-number N --submit-for-review` to submit the uploaded build for Apple review. Report publication only after Apple makes it available.

## Rollback

Revert the introducing commit and publish a new patch, without force pushes or retagging. Preserve the local SQLite database. Destructive data migrations require a separate, reviewed migration and backup strategy.

## Verified native behavior

The user confirmed systemwide Command + Space, automatic search focus, Escape dismissal and outside-click dismissal in the public-API window build. Command + Delete was then verified against a populated search. Installation checks used the actual external CLI: jq, Inter and Rectangle, with apps in the user Applications directory and fonts in the user Fonts directory. These development observations must be repeated for the exact signed release where relevant.

The Store edition retains the same Pantry features and discloses the external CLI architecture in review notes. A Developer ID build of the same application is used for local qualification. There is no separate edition that hides installation behavior from App Review.

The native Keychain check found and fixed a Craft persistence defect before release. Craft 0.0.365 stores credentials through Security.framework, reports denied reads and failed writes, and preserves existing credentials when an update fails. A real Launchpad quit and relaunch restored the Pantry connection and installed package list.

Signed qualification exposed a Keychain authorization wait on the main thread. Craft 0.0.366 moves credential operations to owned workers and returns through the shared reply pool. Launchpad registers its shortcut before restoring optional integrations, so those integrations cannot delay the primary launcher.

Craft 0.0.367 treats Keychain access as an interactive native request, preserving the pending request until macOS answers instead of timing out during system authentication. The signed, sandboxed qualification build verified Command + Delete clears search while preserving saved commands, and Return selects a package filter without launching the selected search result. Saved connection checks show their pending state and support retry after a denied request. Authorization for credentials created by the earlier development build remains a user-controlled macOS step on this machine.

Signed Build 11 also captured the known calculator result `252` while the palette was hidden and rendered the saved text preview after reopening. The original paused setting and seven-day retention were restored after this check.
