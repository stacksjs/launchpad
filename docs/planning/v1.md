# Launchpad v1

Build a local, keyboard-first macOS launcher with Stacks models, stx, ts-css and Craft. Command + Space brings a compact search palette to the front from another app. Data stays in the app's Application Support directory. No account or remote service is required.

## Scope

| Capability | v1 delivery | Qualification |
| --- | --- | --- |
| Application launcher | Search, fuzzy ranking, Return to open | Real native window and cross-app hotkey test |
| Calculator | Bounded arithmetic, powers, percentages, copy result | Parser tests plus native copy |
| Quicklinks | Named URLs and encoded search arguments | Persistence, scheme validation and actual browser opening |
| Snippets | Named reusable text, aliases, copy | Model validation and native clipboard |
| Favorites and recents | Per-item favorites, usage ranking | Survive an application restart |
| Clipboard History | Opt-in automatic text capture, preview, retention, pause and clear | Native capture, protected types, local persistence |
| Appearance | System, Light and Dark | Real native screenshots in both modes |
| GitHub | Repository, issue, pull request and personal work views | Public API search, Keychain token, safe external URLs |
| Local activity | UUID events, sessions, categories, timestamps and timezone offsets | Idempotent local API, pause/delete, aggregation tests |
| App Store delivery | Sandboxed signed package, accurate metadata and screenshots | Signed launch, upload processing, review approval |

Year-review image export, arbitrary extensions, global text expansion and window control are separate issues. They must have verified privacy and platform support before inclusion. A local feature build is not proof of sandbox compatibility or App Store approval.

## Data flow and architecture

The Craft host launches stx's compiled backend and owns its lifetime. stx creates an ephemeral loopback session with a one-time token, HttpOnly cookie, same-origin and Host checks. The page uses same-origin fetch. The backend opens SQLite through `@stacksjs/orm/native`, with an explicit registry of the app's Command, LaunchRecord, ClipboardEntry, AppPreference and LauncherActivity models. Their `useApi` traits declare CRUD; writes use native model validation and fillable fields. Destructive schema upgrades fail before commit.

Application search reads the standard application directories. Launching uses Craft's NSWorkspace-backed shell interface. Systemwide shortcuts use Craft's Carbon registration, and must be proven by actual key presses while another application has focus. A registration conflict is reported in the UI.

The native model adapter is a reusable framework addition. Launchpad links the built core package during development and must pin a published version containing it before reproducible release qualification. Pantry owns immutable runtime provisioning, signing, notarization, packaging and delivery. Application code must not duplicate those processes.

## Verification matrix

| Scenario | Required result |
| --- | --- |
| Cold start without installed Bun | App and bundled backend become ready |
| Press Command + Space in another app | Existing palette appears and focuses search |
| Conflicting shortcut | Explicit error, no false registration success |
| Search, arrows, Return, Escape | Selected item launches; palette dismisses and reopens |
| Invalid command fields | 422, no invalid database row |
| Create snippet and restart | Snippet survives and copies accurately |
| Favorite and relaunch | Favorite remains and ranks first |
| Unauthorized loopback request | 403 before data access |
| New additive model column | Existing rows survive |
| Destructive model diff | Refused atomically |
| Sandboxed signed launch | Same behavior inside the actual app container |
| Store package upload | Apple reports accepted upload and processed build |

## Release sequence

1. Complete and qualify the core native model adapter; publish Stacks patch.
2. Install that version in Launchpad; remove the development link and repeat verification.
3. Commit as Chris and fast-forward origin/main. Configure the Pantry reusable workflow.
4. Run `bun run release:patch` for the installable qualification build.
5. Complete remaining v1 acceptance criteria and signed sandbox qualification.
6. Cut marketing version 1.0.0 with an immutable numeric build number; upload the same signed artifact.
7. Complete truthful privacy, age, export and pricing declarations and submit for Apple review. Report publication only after Apple makes it available.

## Rollback

Revert the introducing commit and publish a new patch, without force pushes or retagging. Preserve the local SQLite database. Destructive data migrations require a separate, reviewed migration and backup strategy.
